# 분류 체계 설계하기

분류 체계는 원장의 코드 트리입니다: 대분류 → 중분류 → 작업 → 단계. 온보딩 때 에이전트가 기록을 훑어 분류 체계를 제안하고, 승인을 받기 전에는 행을 하나도 쓰지 않습니다. 이 가이드는 그 제안을 판단하는 데 도움을 줍니다. 행이 생기면 코드는 바꾸지 않으므로 처음 구조가 중요합니다.

## 네 단계

| 단계 | 코드 | 무엇인가 | 예 |
|---|---|---|---|
| 대분류 | `1` | 해가 바뀌어도 이어지는 삶의 영역, 4~7개 | `1 연구` |
| 중분류 | `1.2` | 한 해 안의 프로젝트, 산출물 흐름, 반복 업무. 작업 3~40개 | `1.2 워크숍 논문` |
| 작업 | `1.2.3` | 정확한 날짜와 근거가 있는 산출물·결정·사건 하나 | `1.2.3 A0 포스터와 3분 발표 대본` |
| 단계 | `1.2.1.4` | 하나로 이어진 작업 안에서 날짜가 따로 있는 단계 | `1.2.1.4 채택 통보` |

## 대분류: 4~7개, 오래 가는 것으로

- 대분류는 프로젝트가 아니라 영역입니다. 프로젝트는 끝나지만 영역은 이어지므로, 같은 대분류 목록을 해마다 씁니다.
- 흔한 구성:
  - 창업도 하는 대학원생: `1 연구`, `2 진학`, `3 창업·제품`, `4 대외·경력`, `5 개인 행정`
  - 직장인: `1 제품`, `2 운영`, `3 팀`, `4 학습`, `5 개인 행정`
  - 프리랜서: `1 고객`, `2 사업`, `3 기술`, `4 커뮤니티`, `5 개인 행정`
- 행정에는 대분류를 따로 주세요. 세금, 등록, 갱신, 서류는 실제로 시간이 드는 일이고, 숨기면 검진 결과가 틀어집니다.
- 맞는 것이 없을 때만 끝에 새 대분류를 더하고, 번호는 바꾸지 않습니다.

## 중분류: 연도별로, 작업 3~40개

- 중분류는 "요즘 뭐 해?"라는 질문에 답할 때 댈 이름입니다: 논문 한 편, 배포 하나, 맡은 수업, 지원 한 차례, 지원사업 하나.
- 너무 크면(한 해 40개 이상): 산출물이나 국면으로 나눕니다. 예: `3.1 v1 출시`, `3.2 성장·운영`.
- 너무 작으면(3개 미만): 이웃 중분류에 합칩니다. 예: 일회성 구매는 `5.2 장비·구독`으로.
- 반복 업무(수업 조교, 장부 정리, 주간 보고)도 중분류입니다.
- "기타"는 피하세요. 거기 들어가는 것은 아직 이름을 붙이지 않은 중분류입니다.
- 중분류 번호는 해마다 `x.1`부터 새로 매깁니다. 같은 프로젝트도 해가 다르면 번호가 다를 수 있습니다.

## 작업과 단계: 원자 단위로

원장은 원자료이고 요약이 아닙니다.

- 한 행은 구체적인 산출물·결정·사건 하나이고, 출처의 정확한 날짜(메시지 시각, 커밋 날짜, 파일 시각, 메일 시각, 일정 날짜)와 근거 포인터를 하나 이상 가집니다.
- 좋은 예: `본 학회 투고`(2026-05-13). `3장 방법 22쪽, 그림 9개`(2026-02-16 ~ 02-28, 하나로 이어진 집필).
- 나쁜 예: `논문 작업(5월)`, `10-10 ~ 10-13: A, B, C 함`. 날짜가 있는 행으로 나눕니다.
- 날짜가 따로 있는 단계가 여럿인 작업은 상위 작업이 됩니다. 작업은 코드·제목·전체 기간을 유지하고, 단계는 각각 레벨 4 행이 됩니다.
- 나중에 나온 결과는 새 행입니다. 채택 통보는 "투고" 행에 덧붙이는 메모가 아니라 별도 행입니다.
- 날짜를 모르면 비워 둡니다. 수집 작업이 계속 찾고, 아무도 추측하지 않습니다.

## 목표: 결과 3~6개

- 목표는 `plan.csv`(`목표` 행)에 두고, 각 작업은 그중 하나에 기여할 수 있습니다.
- 활동이 아니라 결과로 씁니다: "박사 지원하기"가 아니라 "2027년 박사 과정 합격".
- 대시보드는 시간이 실제로 어디에 쓰이는지를 중요하다고 말한 것과 비교하므로, 짧고 솔직한 목록이 긴 목록보다 낫습니다.

## 연도

- 연도마다 같은 대분류로 트리가 따로 있고, 중분류는 `x.1`부터 다시 시작합니다.
- 새해로 이어진 작업은 시작한 해에 남습니다. 새해에 그 작업으로 한 일은 새해 트리에 `(계속)`으로 시작하는 새 행이 됩니다.

## 코드는 바꾸지 않습니다

- 코드 번호는 다시 매기지 않습니다. 지운 행의 코드는 폐기되어 빈 번호가 생기는 것이 정상입니다. 잘못 분류한 행은 새 코드로 옮기지 않고 내용에서 바로잡습니다.
- 그래서 처음 구조가 가장 중요합니다. 대분류가 내년에도 맞고, 가장 바빴던 해에 중분류가 잘 맞아 보일 때 승인하세요.

## 승인 전 점검표

- [ ] 대분류 4~7개, 각각 내년에도 있을 영역
- [ ] 모든 중분류가 그해 작업 약 3~40개이고, "기타"가 없음
- [ ] 반복 업무와 행정에 각자 중분류가 있음
- [ ] 목표 3~6개, 모두 결과로 표현
- [ ] 예시 행 다섯 개가 정확한 날짜와 근거가 있는 구체적인 산출물·결정·사건으로 읽힘

## 예시(가상)

```
2026
1 연구          1.1 학위논문 집필 · 1.2 학회 논문 · 1.3 저널 확장 · 1.4 연구실 세미나 · 1.5 문헌 조사
2 진학          2.1 박사 지원 · 2.2 장학금
3 창업·제품     3.1 Sproutlog 출시·배포 · 3.2 성장·운영 · 3.3 지원사업·투자
4 대외·경력     4.1 조교 · 4.2 발표·네트워킹 · 4.3 인턴십
5 개인 행정     5.1 학적·서류 · 5.2 장비·구독 · 5.3 세무·회계
목표: 석사 학위 마무리 · 2027년 박사 과정 합격 · 연구 성과 출판 · Sproutlog 성장 · 행정 기한 준수
```

가상의 전체 원장은 `sample/ko`(한국어)와 `sample/en`(영어)에 있습니다.
